## 一、为什么改方向

原方案先做时间窗口盘，理由是「不依赖当前比分」。跑完发现两个问题：

**1. 窗口盘本身没什么可看的**

```
59,475 组完整窗口盘
最低 Σ = 1.0710    中位 = 1.1300
< 1.00 的：0 组
```

零命中是预期内的，但它同时意味着：页面上那一大块「窗口盘成本」
永远是「一片正常」，对用户没有信息量。

**2. 窗口盘把红黄牌/角球混进来了**

`Total Bookings`、`Total Corners`、`Corner 1x2` —— 这些是角球和牌，
不是「比赛结果」。用户要的是「这场比赛最后会怎样」。

**结论：改做「比赛结果盘」，窗口盘完全移除。**

## 二、覆盖范围

### 2.1 全场结果盘（参与判定）

| 盘口 | covers() | 说明 |
|---|---|---|
| `1x2` | ✅ | 胜平负 |
| `Total` | ✅ | 总进球 over/under |
| `Double Chance` | ✅ | 双胜彩 |
| `Both Teams To Score` | ✅ | 双方都进球 |
| `Exact Goals` | ✅ | 每队进球数（含 3+） |
| `Clean Sheet` | ✅ | 零封 |
| `Halftime/Fulltime` | ✅ | 半场/全场 |
| `Highest Scoring Half` | ✅ | 哪个半场进球多 |
| `Odd/Even` | ✅ | 总进球奇偶 |
| `Correct Score` | ✅ | 含 other 补集 |
| `Handicap` | ✅ | 让球 |
| `1x2 & Both Teams To Score` | ✅ | 组合盘 |

### 2.2 半场盘（参与判定，但要按时段过滤）

| 盘口 | covers() | 时段 |
|---|---|---|
| `1st Half - 1x2` | ✅ | 只在 minute ≤ 45 参与 |
| `1st Half - Total` | ✅ | 同上 |
| `1st Half - Double Chance` | ✅ | 同上 |
| `1st Half - Both Teams To Score` | ✅ | 同上 |
| `1st Half - Exact Goals` | ✅ | 同上 |
| `1st Half - Handicap` | ✅ | 同上 |
| `1st Half - Correct Score` | ✅ | 同上 |
| `2nd Half - 1x2` | ✅ | 只在 minute > 45 参与 |
| `2nd Half - Total` | ✅ | 同上 |
| `2nd Half - Double Chance` | ✅ | 同上 |
| `2nd Half - Both Teams To Score` | ✅ | 同上 |

**时段过滤是必须的，实测证据：**

```
第 60 分钟，kessbet_odds_live 里仍有 12 个 1st Half 选项
```

平台赛前就挂了 `1st Half` 盘，滚球时不主动撤。上半场结束后这些盘口
**已经结算**，拿它参与判定会算出「上半场 1x2 还能下注」这种不可能的套利。

反向同理：`2nd Half - *` 在赛前就挂着（实测第 0 分钟就有 349 行），
上半场时它还没生效。

### 2.3 明确排除

| 盘口 | 原因 |
|---|---|
| `Total Corners` / `Corner 1x2` / `Corner Range` | 角球，不是比赛结果 |
| `Total Bookings` / `Booking 1x2` / `Sending Off` | 红黄牌 |
| `N Minutes - * From A To B` | 时间窗口盘，本次移除 |
| `Which Team Wins The Rest Of The Match` | 语义是「剩余时间」，covers() 不支持 |
| `1st Goal` / `2nd Goal` / `3rd Corner` 等 | 事件盘，covers() 不支持 |
| `Draw No Bet` | covers() 不支持（可后续补） |
| `Total (incl. Overtime)` 等篮球盘 | 篮球，暂不分析 |

## 三、核心算法

### 3.0 ⚠️ 两个致命陷阱（实施中实测发现）

这两条是**必须先解决**的，否则算出来全是假信号。

#### 陷阱 1：已兑现的选项会造出 Σ=0.05 的假套利

平台**不会**因为某个结果已经发生就撤掉对应盘口，也不把赔率改成 1.00。

实测（2026-11-12，当前 1:0 第 15 分钟）：

```
Total|H|0.5|over     覆盖 1980/1980 = 100%   ← 主队已进球，必然成立
Total||0.5|over      覆盖 1980/1980 = 100%
Total|H|0.5|under    覆盖    0/1980 =   0%   ← 必然失败
```

而 `Total H 2.5 over @2.25`、`Total A 0.5 under @2.50` 都在正常挂牌
（实测第 15 分钟的真实赔率）。

**不处理的话**：ILP 会立刻发现「买一个必然成立的选项就够了」，
算出 `Σ = 1/1.17 = 0.85`。实测未过滤时 **67% 的快照都被误判成套利**，
最低 `Σ=0.0533`。

**解法**：判定前剔除覆盖率 100% 或 0% 的选项。

```python
def _drop_decided(cands, rm):
    n = bin(rm).count('1')
    return [c for c in cands
            if 0 < bin(c[0] & rm).count('1') < n]
```

#### 陷阱 2：流水表不能用来重建历史快照

`kessbet_odds_live_history` 只记录**变化**和**新增**，
**不记录「撤盘」**。而平台会主动撤：

| 盘口 | 实测行为 |
|---|---|
| `Double Chance` | `1X @1.25` 只在第 0~3 分钟存在，之后换成 `12`+`X2` |
| `Total` | 第 63 分钟只挂 `2.5`，更早的 `1.5` 已被替换 |
| `Correct Score` | 比分逐批替换，不是一次挂全 |

任何「累加」式重建都会让已撤的选项留下来，和当前选项拼出
**真实环境不可能出现的组合**。实测踩到三次：

```
Σ=0.29   Correct Score: 1:0@15 + 0:3@9.25 + 1:4@23 + other@14
         ↑ 这几个比分不可能同时挂牌
Σ=0.81   Total 1.5 over @2.2 + Exact Goals 1
         ↑ 当时平台给的是 Total 2.5 over @2.6，1.5 早就撤了
Σ=0.90   1x2 2 @9.75 + Double Chance 1X @1.25
         ↑ 1X 在第 3 分钟就撤了
```

**「只用同一 changed_time 批次」也不行** —— 一批只有 3~20 个选项，
永远构成不了完整覆盖，评估不出任何结果（实测 42 场跑不完）。

**结论：验证只能用平台实时全量接口。**
`fetch_odds(match_id)` 返回的就是网页上看到的完整盘口，
拿它跑判定结果才可信。历史流水只能用于「看赔率怎么变的」，
不能用于「重建当时的完整状态」。

> 生产侧没有这个问题：`replace_live_odds` 每次拿 HTTP 全量接口覆盖，
> 接口里没有的会真的 DELETE。陷阱 2 只影响回测。

### 3.1 复用 covers()，但要处理「不可达终局」

现有 `covers()` 建立在 2025 个状态 `(h1,a1,h2,a2)` 上，产出 2025 位 mask。

滚球时并非所有终局都可能：当前 1:0 时 `0:0` 不可能。

**不能直接缩小 mask 位宽** —— 实测报错：

```
ValueError: axis 0 index 2024 exceeds matrix dimension 1980
```

**采用的方案（方案 B）：保持 2025 位宽，加一个「不可达状态」的幽灵候选。**

```python
def reach_mask(home, away, ht=None):
    """当前比分下可达的终局，2025 位 mask。"""
    m = 0
    for i, (h1, a1, h2, a2) in enumerate(STATES):
        if h2 < home or a2 < away:
            continue
        if ht is not None and (h1 != ht[0] or a1 != ht[1]):
            continue                 # 下半场时半场比分已固定
        m |= 1 << i
    return m


def solve_live(cands, rm):
    ghost = FULL & ~rm                       # 不可达状态
    pool = cands + [(ghost, 1e9, '__unreachable__')]
    r = solver.solve(pool, NS)               # NS 仍是 2025
    return r.cost
```

**为什么用 1e9 的赔率而不是 0：**
`1/1e9 ≈ 1e-9`，对最优值的影响远小于浮点精度。用 0 会除零，用极小值
能让 solver 选出它（成本几乎为 0）但又不影响结果。

**为什么不用方案 A（重映射到子集）：**

实测两种方法结果**完全一致**，但：

| 方法 | 1:0 下半场（90 状态） | 1:0 上半场（1980 状态） |
|---|---|---|
| A 重映射 | 0.012s | 0.088s |
| B 位宽 + ghost | 0.059s | 0.049s |

B 对可达状态数**不敏感**（因为 n_states 恒为 2025），A 随子集缩小而变快。
但 90 状态时 A 只快 47ms —— 这个差异不值得多写一套重映射逻辑。

**更重要的是 B 更不容易错**：A 要维护一份 index 映射，一旦状态空间
定义改动（比如 `H`/`G` 调整）就会静默错位。

### 3.2 可达终局的规模

| 当前比分 | 阶段 | 可达终局 |
|---|---|---|
| 0:0 | 上半场 | 2025（100%） |
| 1:0 | 上半场 | 1575（78%） |
| 1:0 | 下半场 | 90（4.4%） |
| 1:1 | 下半场 | 81（4.0%） |
| 2:1 | 下半场 | 72（3.6%） |

**上半场几乎没缩小**（1:0 时还剩 78%）—— 因为半场比分未知，
只能锁终局。**下半场才真正缩小到 4%**（半场比分已固定）。

这修正了前一份设计文档的说法：单锁终局不解决问题，
**必须在下半场连 `h1/a1` 一起锁**。

### 3.3 半场比分的来源

下半场需要当前的半场比分。两个来源：

1. `fetch_state` 的 `msScoreList` —— **不可直接使用**。
   实测当前比分 1:0 时它返回两个 `0:0` 的阶段快照，不是半场比分。
2. 从我们自己的流水表反推：取 `minute <= 45` 的最后一条
   `home_score/away_score`。

**首期用方案 2**（数据已在采）。取不到时退化为「只锁终局」，
仍然正确，只是状态空间大一些。

## 四、页面布局

### 4.1 列表页（`/live`）

```
状态 | 比赛 | 比分 | 盘口 | 最低成本 | 套利 | 最后更新
                          ↑        ↑
                    结果盘最小Σ   徽章
```

- **最低成本**：所有「比赛结果盘」组合出来的最小 Σ
- **套利**：`< 1` 时绿色徽章，否则空
- 移除「窗口盘成本」整个区块
- 保留角球/牌列？**移除** —— 用户要的是结果，不是过程数据

### 4.2 详情页（`/live/<id>`）

```
┌─ 计分板：比分 / 分钟 / 状态 / 角球 ──────────────┐
├─ 比赛结果套利判定 ★ 主角 ────────────────────────┤
│   最低成本 1.0852      状态：无套利（抽水 8.5%）  │
│   当前 1:0 第 62 分钟 → 可达终局 90 个            │
│   ┌ 覆盖组合 ────────────────────────┐            │
│   │ 选项              赔率   下注比例 │            │
│   │ 1x2 · 1           1.85   38.2%   │            │
│   │ Total 2.5 under   2.00   29.1%   │            │
│   │ ...                              │            │
│   └──────────────────────────────────┘            │
├─ 赔率走势（点任意选项）───────────────────────────┤
└─ 全部盘口（按盘口分组，结果盘在前）───────────────┘
```

**关键**：命中时给出**具体下注比例**，不是只说「有套利」。

## 六、验收标准

| # | 标准 |
|---|---|
| 1 | 结果盘判定在真实数据上**不产生假信号**（Σ < 1 要能人工复核） |

| 3 | 下半场时可达终局数 ≈ 4% 而不是 78% |
| 4 | 列表页能一眼看出「这场有没有机会」 |
