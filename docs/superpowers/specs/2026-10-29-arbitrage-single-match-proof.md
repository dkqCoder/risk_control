## 第二步：状态空间

### 什么叫"一种可能的比赛结果"

定义成四元组：

```
(h1, a1, h2, a2)

h1 = 半场主队进球
a1 = 半场客队进球
h2 = 全场主队进球
a2 = 全场客队进球
```

**约束**：`h2 ≥ h1` 且 `a2 ≥ a1`（下半场不可能倒扣球）。

### 取值范围与状态数

```
h1, a1 ∈ 0..5   （半场最多 5 球）
h2, a2 ∈ 0..9   （全场最多 9 球）
```

数一下合法组合：

```
h1=0..5, a1=0..5  → 36 种半场比分
对每种半场比分 (h1,a1)，全场 (h2,a2) 有 (10-h1) × (10-a1) 种可能
总和 = Σ(h1,a1) (10-h1)(10-a1) = 2025
```

**2025 个状态。**

### 举例

| 状态 | 含义 |
|---|---|
| `(0, 0, 0, 0)` | 半场 0:0，全场 0:0 |
| `(0, 0, 1, 0)` | 半场 0:0，全场 1:0（下半场主队进 1 球） |
| `(1, 0, 1, 0)` | 半场 1:0，全场 1:0（下半场无进球） |
| `(0, 1, 2, 3)` | 半场 0:1，全场 2:3 |

### 边界外的比分怎么办

**问题**：如果比赛打成 10:0，不在 2025 个状态里，会怎样？

**答案**：落入 `Correct Score` 盘口的 `other` 选项。

- `Correct Score` 的 24 个具名比分覆盖了 0:0 到 4:4 的大部分组合
- `other` 选项的覆盖范围 = `全集 & ~具名比分`
- 所以 10:0 这类极端比分**被 `other` 覆盖**

**但这只解决了比分盘。** 非比分盘（如 `Total 2.5 over`）在 10:0 时仍然成立（总进球 10 > 2.5），逻辑上没问题。

**真正的风险**：如果某场比赛没有 `other` 选项，或者模型判定某个极端状态无人覆盖，会返回 `NO_COVER` 并跳过该场。实测 325 场，0 场 NO_COVER。

## 第三步：选项映射成 bitmask

### 做法

对每个可建模选项，扫描全部 2025 个状态，判断"这个状态下它是否中奖"。

- 中奖 → 对应位设为 1
- 不中奖 → 保持 0

结果是一个 2025 位的二进制数。

### 本场真实覆盖率

**1x2（胜平负）**

| 选项 | 赔率 | 覆盖状态 | 占比 |
|---|---|---|---|
| `1`（主胜） | 1.73 | 895 | 44.2% |
| `X`（平局） | 3.75 | 235 | 11.6% |
| `2`（客胜） | 4.10 | 895 | 44.2% |

**为什么平局只覆盖 235 个？**
平局要求 `h2 = a2`。在 2025 个状态里，满足这个条件的组合只有 235 个。

**Double Chance（双选）**

| 选项 | 赔率 | 覆盖 | 占比 |
|---|---|---|---|
| `12`（分出胜负） | 1.23 | 1790 | 88.4% |
| `1X`（主胜或平） | 1.21 | 1130 | 55.8% |
| `X2`（平或客胜） | 1.86 | 1130 | 55.8% |

**Total（总进球）**

| 盘线 | 选项 | 赔率 | 覆盖 | 占比 |
|---|---|---|---|---|
| 1.5 | over | 1.19 | 2020 | 99.8% |
| 1.5 | under | 3.95 | 5 | 0.2% |
| 2.5 | over | 1.63 | 2010 | 99.3% |
| 2.5 | under | 2.10 | 15 | 0.7% |
| 3.5 | over | 2.55 | 1990 | 98.3% |
| 3.5 | under | 1.44 | 35 | 1.7% |

**`Total 1.5 over` 覆盖 99.8%** —— 因为只有"总进球 0 或 1"的 5 个状态才不满足。

**Both Teams To Score（双方进球）**

| 选项 | 赔率 | 覆盖 |
|---|---|---|
| `yes` | 1.62 | 1936（95.6%） |
| `no` | 2.11 | 89（4.4%） |

**Multigoals（总进球区间）**

| 选项 | 赔率 | 覆盖 |
|---|---|---|
| `1-6` | 1.05 | 207 |
| `2-6` | 1.15 | 203 |
| `3-6` | 1.43 | 193 |
| `1-5` | 1.08 | 125 |
| `3-5` | 1.53 | 111 |

**注意 `1-6` 只覆盖 207 个状态**，看起来很少——但这是对的。

`Multigoals` 的语义是**全场总进球**（`h2 + a2`）。2025 个状态里：

| 总进球 | 状态数 |
|---|---|
| 1~6 | **207** |
| ≥7 | **1817** |
| 0 | 1 |

**大部分状态是总进球 ≥7 的**——因为全场比分可以打到 9:9（总进球 18）。所以"总进球 1~6"只占 10%。

对比 `Exact Goals 6+`（总进球 ≥6）：覆盖 **1899** 个状态，刚好是 207（1~6 中的 6 那部分）+ 1817（≥7）再减去重复。

> 这说明状态空间向高比分倾斜是数学必然而不是建模错误。
> 但也要注意：真实足球比赛里 9:9 的概率趋于零。状态空间是"逻辑完备"，
> 不是"概率加权"——我们只关心"有没有可能发生"，不关心"多大概率"。

### 互补性自检

同一盘口的所有选项，必须满足：

1. **并集 = 全集**（没有状态被遗漏）
2. **交集 = 空**（没有状态被重复计算）

本场 `1x2` 三项：

```
1 ∪ X ∪ 2 = 895 + 235 + 895 = 2025  ✓
1 ∩ X = 0,  1 ∩ 2 = 0,  X ∩ 2 = 0  ✓
```

**验证通过。** 这说明 `covers()` 的建模是对的。

## 第四步：求解最小覆盖成本

### 问题形式化

已知：

- 192 个候选，每个有 `mask`（覆盖的状态）和 `cost = 1/赔率`
- 全部状态 `S`，共 2025 个

求：

```
min  Σ costᵢ · xᵢ           xᵢ ∈ {0, 1}
s.t. 对每个状态 s ∈ S: Σ xᵢ ≥ 1     （所有覆盖 s 的 i）
```

- `xᵢ = 1` 表示买选项 i
- 第 2 行约束有 2025 条，每条对应一个状态

### 求解结果

```
最小覆盖成本 = 1.070349
选中 2 个：
  1x2 | 2          赔率 4.10  覆盖 895 个状态
  Double Chance | 1X  赔率 1.21  覆盖 1130 个状态
```

### 验证覆盖完整性

```
选中项的 mask 取并集：
  895 个状态 + 1130 个状态
  但两者有重叠吗？ 1x2|2 = 客胜，DC|1X = 主胜或平
  两个集合互斥，无重叠
  合计 895 + 1130 = 2025  = 全集  ✓
```

**覆盖 2025 / 2025，完整。**

### 为什么是这组最优

用 1x2 三项算一下作对比：

```
1/1.73 + 1/3.75 + 1/4.10
= 0.5780 + 0.2667 + 0.2439
= 1.0886
```

**全盘最优 1.0703 < 纯 1x2 的 1.0886**，省了 0.018。

原因：用 `1x2|2`（4.10）+ `DC|1X`（1.21）比 `1x2` 三项更便宜。

```
1x2|2 + DC|1X  = 1/4.10 + 1/1.21 = 0.2439 + 0.8264 = 1.0703
1x2 三项        = 0.5780 + 0.2667 + 0.2439 = 1.0886
```

**差额 0.0183 就是"1x2|1 定价偏贵"的部分。**

## 第五步：资金配置（第二套模型）

### 换个角度问同一个问题

模型 1 问的是：**"买哪几个选项？"**

模型 2 问的是：**"每个选项买多少钱？"**

### 求解结果

假设总投注 1 个单位：

```
Double Chance | 1X      0.772128  （77.2%）
1x2 | 2                 0.227872  （22.8%）
```

### 逐状态验算

**如果比赛结果是主胜或平局**（`DC|1X` 中奖）：

```
投入 1 单位
收回 0.772128 × 1.21 = 0.934275
已投入的 1x2|2 打水漂
净收益 = 0.934275 - 1 = -0.065725
```

**如果比赛结果是客胜**（`1x2|2` 中奖）：

```
投入 1 单位
收回 0.227872 × 4.10 = 0.934275
已投入的 DC|1X 打水漂
净收益 = 0.934275 - 1 = -0.065725
```

**两种情况净收益完全相同：-0.065725。**

这就是最优解的特征——把最差情况拉到最高（虽然还是亏）。

### 换算成金额

投 1000 元：

| 结果 | 投注分配 | 中奖收回 | 净收益 |
|---|---|---|---|
| 主胜或平 | DC|1X 772.13 元 | 772.13 × 1.21 = 934.28 元 | **-65.72 元** |
| 客胜 | 1x2|2 227.87 元 | 227.87 × 4.10 = 934.28 元 | **-65.72 元** |

**不管什么结果，你都亏 65.72 元。这就是 6.57% 的抽水。**

## 第六步：两套模型的交叉验证

### 理论上它们应该等价

模型 1 算出最小成本 `C = 1.070349`。

这个 `C` 的含义是：**花 1.070349 单位，能保证收回 1 单位。**

换算成"投 1 单位，最差收益"：

```
最差收益 = 1/C - 1
        = 1/1.070349 - 1
        = 0.934275 - 1
        = -0.065725
```

**模型 2 算出的最差收益：-0.065725。**

### 实测

```
模型 1 隐含：  -0.065725047
模型 2 实际：  -0.065725047
差异：         0.00e+00
```

**完全一致，误差为 0。**

### 为什么不一致会说明有问题

如果某天差异超过 `1e-4`，说明：

- `covers()` 的建模有误（比如某个盘口覆盖范围算错）
- 或者求解器返回了错误结果
- 或者有停售选项混入（赔率 ≤ 1.0）

代码里会 `log.error` 告警。

## 第七步：结论

### 成本

```
1.070349 > 1.0
```

### 判定

**无套利。**

投入 1.07 元才能保证收回 1 元，**净亏 6.57%**。

### 这 6.57% 是什么

**平台抽水。**

对比平台其他盘口的单项抽水：

| 盘口 | Σ(1/赔率) |
|---|---|
| 1x2 | 1.0886 |
| 1x2 + Double Chance 组合（最优） | **1.0703** |

**最优组合的 1.0703 = 平台的真实抽水水平。**

## 第八步：这个结论有多可信

### 支持这个结论的证据

| 项 | 结果 |
|---|---|
| 覆盖完整性 | 2025 / 2025 ✓ |
| 互补性自检 | 1x2 三项并集=全集、交集=空 ✓ |
| 两模型交叉验证 | 差异 0.00e+00 ✓ |
| 停售过滤 | 已排除赔率 ≤ 1.0 的选项 ✓ |
| 全量扫描 | 325 场，0 场 NO_COVER，0 场套利 ✓ |

### 这个结论**不能**证明的事

**① 未建模盘口可能存在套利**

114 个选项没参与计算，包括：
- `Correct Score` 的具名比分（只用了 `other` 补集）
- `Draw No Bet`、`Draw Or Over 2.5` 等复合盘口
- `To Win Both Halves` 等特殊盘口

**如果某组套利只存在于这些盘口的组合里，会漏掉。**

但反过来看：这些未建模盘口的定价通常**更贵**（抽水更高），不太可能构成套利来源。

**② 状态空间有上界**

只覆盖到"单队 9 球"。10:0 这类极端比分依赖 `other` 选项的覆盖。

实测 325 场，`other` 都在候选池里，覆盖完整。

**③ 赔率是快照**

15:45 开赛，数据采集于 2026-10-29 上午。**实际下注时赔率会变。**

**④ 数学套利 ≠ 可执行套利**

即使算出 `cost < 1`，还需要：
- 赔率在你下注时仍然有效
- 所有投注都被接受（有单笔限额）
- 结算规则与模型一致
- 平台承认这笔交易

**本场结论是"模型内无套利"，不是"现实中无法套利"。**

## 附录 B：为什么不能用贪心

用本场的真实赔率模拟贪心（每次选"每格成本最低"的）：

```
第 1 步：Total 1.5 over
        覆盖 2020 个状态（99.8%），成本 1/1.19 = 0.8403
        剩余未覆盖：5 个状态（总进球 0 或 1）

第 2 步：需要覆盖那 5 个状态
        可选 Exact Goals 1（覆盖 4 个，成本 1/5.6 = 0.1786）
        → 选它
        剩余：1 个状态（总进球 0）

第 3 步：Exact Goals 0（成本 1/15.0 = 0.0667）
        剩余：0

贪心总成本 = 0.8403 + 0.1786 + 0.0667 = 1.085574
```

**真实最优是 1.070349，贪心差 0.015225。**

### 贪心错在哪

它被"覆盖面最大"吸引，选了 `Total 1.5 over`（成本 0.84），
但后面要补 3 个零碎的 `Exact Goals`。

而最优解完全不用 `Total`，只用两个盘口：

```
1x2 | 2        成本 0.2439
Double Chance | 1X  成本 0.8264
合计             1.0703
```

**精确求解能一眼看出"1x2 组合比 Total + 补丁更便宜"，贪心看不出来。**

### 更极端的例子

如果第一步选了 `Total 2.5 over`（覆盖 2010 个，成本 0.6135），
看起来"每格成本更低"，但剩余 15 个状态要补更多，结果会更差。

**贪心的结果严重依赖选择顺序，本质上不可靠。**
