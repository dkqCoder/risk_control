# 滚球套利完整功能设计

版本：设计稿 v1，2026-11-17（北京时间）  
范围：KessBet 足球常规时间滚球；不含自动下注。  
依据：用户确定的“获取数据 → 固定当次盘口和状态 → 正确计算 → 命中保存同次原始数据；未命中等待下一次变化”。本文为后续开发和验收的主设计；旧审核及开发清单保留问题背景。

## 1. 完成后的用户体验

系统接到盘口、赔率、可售状态、比分或比赛阶段变化后，取得一份完整的单场数据。每份有效输入有唯一 `snapshot_id`。计算从头到尾只使用这一份快照；新变化生成下一份，不修改前一份。

页面把结果明确显示为“当前已验证候选”“未发现候选”“无法判定”“已失效/已过期”之一。只有模型能证明无界结果域内按实际配资的最低收益为正，且同次平台接口响应含完整报价与可售标记，才称“当前已验证候选”。这证明的是平台接口报价和模型结论，不承诺页面展示或实际成交。

命中时保存可离线回放的证据包。未命中时保留轻量分析记录，等待下一次变化；原始快照可短期存放并按保留规则清理。截图和浏览器页面核验异步运行，失败不抹掉已保存的接口证据，也不提高其证明等级。

## 2. 证据要证明的四件事

1. **内部计算发生过**：固定输入、算法版本、选中组合和计算结果可回放。旧快照 #486 属于此类。
2. **平台接口返回过报价**：同一次 HTTP 响应中的原始盘口、选项 ID、赔率、可售标记与计算输入精确关联。记录本机请求时间区间、目标地址、请求参数、响应状态和内容哈希。它支持“采集程序在该时间区间收到这组平台接口数据”，不能单独证明服务端原子定价或独立可信时间。
3. **页面在某次观察时展示过**：浏览器自身收到的网络响应、对应 DOM、可视区域及截图在同一浏览器会话中逐项关联。页面观察必须有自己的时间，不得倒填为第2项接口快照的时间。页面展示不等于可投注。
4. **实际成交**：每条腿的受理记录、受理赔率、金额和结算规则。此次不实现；界面不得显示“已成交”或“保证可下注”。

证据等级使用 E0（内部回放）、E1（接口原始数据完整且同请求绑定）、E2（页面网络与 DOM 同观察逐项核对）、E3（实际受理）。**计算验证状态单独存储**：E1/E2 并不自动表示套利；模型验证失败时再高等级的报价证据也只证明报价存在。

## 3. 端到端状态机

每场维护 `generation`、`current_snapshot_id`、`current_analysis_id`、`current_status` 和 `status_reason`。状态转换与历史事实分离；历史快照和命中不因当前状态变化而改写。

- `waiting`：尚无可用完整报价；首次发现比赛时进入采集。
- `fetching`：取得请求前状态、原始盘口响应、请求后状态。
- `invalid_input`：网络/协议/解析失败，或状态前后不一致。立即撤销旧机会，按原因重试。
- `ready`：原始响应和规范选项在同一事务中发布为不可变快照。
- `analyzing`：对固定快照计算。并发新快照可产生下一任务，但本任务不得读取新数据。
- `no_candidate`：在已支持的策略范围内未找到候选；撤销旧机会，不宣称全市场无套利。
- `unverifiable`：规则不明、半场来源未知、求解超时、输入不完整或独立验证无法证明；撤销旧机会，保留原因。
- `verified_candidate`：组合通过无界收益验证，且接口报价身份、可售标记和来源完整；持久化命中及证据包。
- `expired`/`invalidated`：报价超时、比分或阶段变化、删盘、停售、终场或更新失败。历史证据仍可查看，当前机会立即消失。

由当前快照版本和有效期限计算当前状态，不能只凭结果表中的 `cost < 1`。任何无法确认当前有效性的分支都不沿用旧机会。

## 4. 触发与输入采集

### 4.1 触发源

- 首次进入滚球比赛列表。
- WS 中盘口增加、更新、删除、锁定/解锁。WS 是刷新/失效信号，不直接当作完整报价。
- 状态轮询发现比分或经确认的阶段变化；立即清空当前机会并重取完整赔率。
- 定期对账，补 WS 断线、漏推送和长期不变的报价；不以每2秒全量重算替代变化检测。
- 规则/解析器/分析器版本升级后，对仍有效的快照重新分析并标明新版本。
- 有效期限到达：只做失效处理，不需要把同一输入重复求解。

同场触发可短时合并；输入指纹由规范盘口、选项身份、可售状态、比分、阶段、可信半场上下文及规则/策略版本计算，不含纯接收时间。指纹相同可跳过求解，但仍更新观察时间和失效期限。系统应说明可能漏掉合并窗口内的瞬时价格；若业务要求逐次报价全处理，改用逐快照队列。

### 4.2 HTTP 结果必须区分

采集接口返回结构化结果，不再仅用 `[]` 同时代表四种情况：

- `ok_nonempty`：成功且响应结构完整，存在可解析盘口。
- `ok_empty`：成功且明确表示当前完整市场为空；可发布空快照并标记无可售报价。
- `transport_error`：超时、403、连接断开或服务端错误；保留旧历史，但当前机会失效并重试。
- `protocol_error`：HTTP成功但响应结构缺字段、类型错误或分页/列表不完整；当前机会失效，保留原始诊断样本。
- `parsed_empty`：原始市场非空，但所有选项被锁定、无效或不支持；保存原始样本和逐项排除原因，当前无可认证报价。

`ok_empty` 只能在接口语义确认“这是该场完整市场”后使用；不能把未授权或残缺返回解释为整场撤盘。WS delete 保存市场 ID、事件时间和原始消息；能映射时立即失效相关候选，映射不可靠时整场失效并全量重取。

### 4.3 固定快照

采集顺序：状态前 → 赔率原始响应 → 状态后。保存准确的请求开始、响应接收时间。状态前后比分或阶段不一致则不发布可分析快照，继续重取。状态接口 `None` 表示未知/失败，只有明确终态码才结束比赛。

快照包含：事件身份与队伍方向；原始请求和响应信封；完整 `mari` 列表；原始/规范选项及平台市场/选项 ID；赔率原值与可售标记；状态前后；比分、阶段、时钟；半场比分及来源/可信状态；解析器、过滤策略和规则版本；请求与接收时间；输入指纹。原始材料和规范材料同时保存，过滤原因可追溯。请求头中的凭据、Cookie 和个人信息不得写入可下载证据包。

赔率缓存、快照、generation 和当前指针在同一事务发布。按 `snapshot_id` 读取分析输入；禁止按“最近时间”拼 raw。若原始存档失败，可以保存 E0 诊断结果，但不能发布有接口证据的正式命中。重试与并发使用幂等键、每场串行锁或 generation 条件写入，旧任务不得覆盖新当前状态。

## 5. 阶段和半场比分（F05）

当前代码已把从赔率流水推断的半场比分冻结进快照，但“冻结”只保证前后一致，不保证值正确。阶段由平台明确状态字段或经过现场验证的阶段转换规则确定；分钟数只作辅助，补时可能使上半场分钟大于45。阶段未知时，依赖阶段的盘口不可认证。

半场比分来源分级：`official_state`（平台明确字段且语义已核实）、`observed_interval`（持续观察到的中场状态）、`inferred_history`（当前启发式赔率流水）、`unknown`。每项保存原始字段/观察事件 ID 与校验结果。必须检查 0≤半场比分≤当前全场比分及前后阶段一致。`inferred_history` 不能作为缩小认证结果域的权威依据。

首期认证仅使用常规时间**全场**白名单盘口，独立验证器从当前全场比分出发，不依赖半场比分。有限模型找候选时若半场上下文不可信，不能用错误半场比分缩窄候选结果域；无法保守建模就返回 `unverifiable`。恢复半场盘前，先取得权威阶段与比分来源，并增加补时、中场、状态回退、比分更正的测试。

## 6. 套利计算与认证

### 6.1 两级计算

第一级从可售且语义已知的盘口寻找候选。现有有限 `soccer.STATES` 可作为候选搜索加速，但它可能漏报，不能作为完整性证明。Correct Score `other` 在固定结算规则获得验证前继续隔离；不得按当前具名选项求补集。

第二级对选中组合独立计算最坏收益。首期白名单：常规时间全场 1x2、Double Chance、BTTS、半球线全场/球队总进球。独立验证器必须覆盖当前比分之后的**无界**整数终局，输出最低返还和亏损反例；任何未知、超时或不支持规则都不能认证。新增盘口类型时，必须先实现其结算函数和完备性论证。比分盘、半场盘、让球、奇偶、退款/半赢半输盘在规则证明前不进入认证。

配资按可实际提交的金额单位取整；用取整后的各腿金额、赔率和真实结算规则复算每个结果的返还，达到配置的最小净收益门槛才认证。ghost 候选只用于内部求解，不计入真实成本。重叠覆盖时返还可能高于最低值，界面不能写“任何结果返还相同”。

### 6.2 结果写入

`verified_candidate` 须同时满足：输入有效且未过期；组合各腿可售身份及报价可在同请求原始响应中逐项对应；规则版本已确认；独立无界与金额取整验证通过；证据保存成功。求解器给出低于1的成本但未满足以上条件，只保存内部候选或无法判定状态，不写“已验证套利”命中。

未命中写 `no_candidate` 轻量分析记录；无法判定写具体原因。两者都使上一当前机会失效。即时回调、周期补偿及CLI共用同一分析服务与写入资格；关闭 `LIVE_ANALYZE_ENABLED` 时全部正式入口不写库，显式诊断只计算不发布。

## 7. 证据包与固定页面

每次已验证命中产生独立 `evidence_id`，与 `analysis_id`、`snapshot_id`、组合指纹和generation关联。证据包至少包含：

- `manifest.json`：格式版本、文件名、字节数、SHA-256、生成时间、输入与模型版本。
- `request.json`：脱敏后的请求 URL、方法、body、必要headers、请求开始及响应接收时间；平台服务端时间仅在实际存在时记录。
- `response.json`：完整原始响应及状态码/关键响应头，或明确说明平台接口工具仅提供提取后的字段；不得把重新序列化列表称为HTTP原始字节。
- `normalized.json`：全部选项、平台身份、锁定状态、排除原因和与原始字段的对应关系。
- `state.json`：请求前后状态、比分/阶段、半场来源及可信度。
- `analysis.json`：策略版本、候选、每腿价格与金额、独立最低收益、反例检查及结论。
- `verification.json`：接口逐项匹配结果；页面取证若存在则附独立页面观察时间、网络响应、DOM、截图和每腿核对结果。

先写临时目录，全部文件和哈希完成后原子发布 manifest 与数据库状态。证据包长期保留，不因临时快照清理而损坏。`/evidence/<id>`只读取该固定记录；不读当前赔率表。旧快照无原始响应时明确 E0，不补造数据。

未命中快照允许短期保留，清理必须排除在途分析、待取证任务及命中引用。命中记录使用 `(snapshot_id, analyzer_version, strategy_fingerprint)` 等幂等键；不能仅凭秒级赔率时间去重。

## 8. 页面同观察核验

页面取证作为异步、持久且有界的任务；不阻塞主计算和接口证据存档。每任务隔离浏览器上下文、页面目标及文件。CDP 必须记录实际 URL、事件身份、浏览器网络报价响应、DOM 选项、可售视觉/属性状态及截图时间。

页面核验逐腿按平台选项 ID 优先匹配，辅以市场、盘线、队伍方向、标签和赔率；重复文本或无法映射 ID 时标 `ambiguous`。展开 All、折叠区及滚动容器，确认每条腿在同一可追溯浏览器观察状态下出现。点击 All、截图大于1KB或图片里没看到盘口，都不足以逐项认证。

接口快照与页面取证时间不同：后续页面变价记 `quote_changed`，撤盘记 `later_removed`；不改写历史接口报价。页面响应、DOM和截图无法关联时保持 E1。即使 E2 成立，仍不能声称实际下注会被接受。

## 9. API 与展示

动态列表、详情和成本接口都通过同一 `current_result_state` 逻辑判断：当前快照ID匹配、generation不落后、分析状态有效、报价年龄未超阈值、比赛仍进行中、判定开关状态明确。`cost=NULL` 必须安全序列化，统计只计有效已验证候选。`/api/live/result-costs`也须执行这些条件，不能继续对NULL做 `float()` 或把历史命中计作当前机会。

页面同时显示：输入版本、报价接收时间与年龄、模型验证状态、接口证据等级、页面证据等级、最低收益及限制。动态盘口的“组合标记”只有同快照/同平台选项ID/同赔率时显示；固定证据页可展示历史组合。`no_candidate` 不写“所有盘口无套利”，`unverifiable` 不显示成“无套利”。

## 10. 影子模式与上线门槛

影子模式与正式开关分离：正常采集、固定快照、运行新模型及生成诊断证据，但**不写正式套利命中、不发正式机会告警**。历史记录与影子记录使用独立状态/表或明确标志，避免混淆。

验收样例至少包括：

1. 9:0和7:0的小9.5+客队大0.5，均给出10:0两腿全输反例。
2. `Correct Score|other` 在具名比分锁定或移除后不扩大覆盖；默认不认证。
3. 一组规则已确认、同请求报价完整且无界最低收益为正的正向样例可以通过，防止“全部拒绝”伪装成修复。
4. 同分不同时段、补时、中场、未知阶段、半场比分大于当前比分、比分更正均保守处理。
5. 成功空市场、网络失败、结构错误、解析后全过滤、WS删盘分别进入正确状态；旧机会立即失效。
6. 比分变化但无赔率推送时主动重取；报价变化但比分未变时重新计算；重复同内容不重复落命中。
7. A/B请求同秒及乱序完成，raw、规范输入、状态和命中不串版；旧generation不能覆盖新状态。
8. 结果无覆盖、求解失败、过期、终场及开关关闭后，列表、详情、成本接口一致撤销当前机会。
9. E0/E1/E2每级证明范围正确；All截图无逐项DOM不升E2；页面后续变价不篡改接口历史。
10. 证据包离线可复算；文件损坏、任务崩溃、队列满、截图失败时状态和重试可追溯。

先通过单元与数据库事务测试，再以真实浏览器、真实数据库运行影子模式，核对正反样例、误报率、证据完整率、采集延迟和失效延迟。正式恢复 `LIVE_ANALYZE_ENABLED=True` 前，必须完成迁移、部署配置检查、告警/页面核对和回滚演练。旧历史快照不自动升级证据等级；有明确错误的记录保留原始材料并追加无效原因。

## 11. 分阶段交付

1. **正确性与状态闭环**：修复成本接口NULL/过期统计；完成F03结果分类、WS删除路由、F05权威阶段/半场来源；统一当前状态和失效规则。
2. **可回溯接口证据**：完整请求/响应信封、选项ID映射、命中证据包导出、固定页和离线回放。
3. **页面证据**：浏览器网络响应与DOM逐项核验、截图关联、异步任务持久化和分级展示。
4. **影子与上线**：正反样例、故障注入、真实环境核验、指标观察和恢复正式判定。

任何阶段都不靠关闭验证器或扩大有限比分上限来获得“通过”。每个新增市场只有在规则、证据映射及完备性测试同时完成后才进入正式认证范围。

## 12. v1 收敛开发记录（2026-11-17）

- Task 2：快照请求/响应信封、响应哈希、输入指纹、解析/规则版本；命中按指纹幂等。
- Task 3：阶段/半场来源分级；半场盘整体隔离；推断半场不用于缩小认证结果域。

- Task 5：当前状态机映射（verified_candidate/no_candidate/unverifiable/invalid_input/expired/invalidated/shadow_candidate）；API/页面一致；cost=NULL 安全；WS 删盘保守失效并重取。

## 13. 多结算范围扩展记录（2026-11-18）

全场比分盘继续使用无界比分验证器。新增的独立范围只在影子模式计算，按输入 `snapshot_id` 保存到 `kessbet_live_scope_analysis`；读取入口为 `/api/live/{match_id}/scopes`。它们不写正式套利命中，也不与全场盘口直接拼接，因为跨范围组合需要联合比赛路径验证。

- **进行中的上半场**：对同一快照中 `1st Half - *` 的进球结果盘去掉前缀，作为独立的上半场终局问题求解，以当时全场比分为上半场当前比分下界；由原有白名单和无界反例验证器复核。只在 `ms=6/7`、阶段判断为上半场、时钟严格小于 45 分钟且比分齐全时运行；45 分钟及补时、阶段/时钟不明、比分接近有限模型上界时返回 `unverifiable`。不混入全场或下半场盘口。当前阶段判断仍由时钟推断，因此仅记影子结果；正式认证还需权威阶段来源与官网选项可选证据。
- **上半场第 N 球及其与 1x2 的组合**：`1st Half - Nth Goal` 仅在当前上半场总进球数小于 N，且 `1/2/none` 三项齐全时单独验证。若同快照还有完整的 `1st Half - 1x2`，额外建立“半场终场胜平负 × 第 N 球归属”的联合结果域：第 N 球未发生时枚举余下少于 N 所需球数的比分；若由任一队进第 N 球，后续进球仍可使半场终场成为胜、平或负。这样可组合两个盘口且不会把终场比分误当进球顺序。第 21 分钟 1:0 的真实快照回放中，两个盘口联合最低成本为 1.1044，非套利。仍只保存影子结果。
