# bet365 赔率抓取

## 现在能不能用

**部分能用，有一条明确的硬限制。**

自检命令：

```bash
py tools/bet365_probe.py
```

它逐个接口探活并打印字节数。当前实测结果：

| 接口 | 用途 | 实测 |
|---|---|---|
| `homepagecontentapi/pod` | 首页精选比赛赔率 | ✅ 261 KB / 9 场 / 33 个选项 / 5 种盘口 |
| `splashcontentapi/soccertab` | 足球页内容（全盘口入口） | ❌ 200 但 0 字节 |
| `splashcontentapi/getsplashpods` | 同上（带 tzo 参数） | ❌ 200 但 0 字节 |
| `matchbettingcontentapi/coupon` | 单场全盘口 | ❌ 200 但 0 字节 |

空响应**不是参数写错或 token 缺失**。下面的对照可以排除这两点：

- 真实 Chrome（chrome-devtools 协议，非 headless 伪装）里页面自己发的
  `soccertab` 请求，响应头 `content-length: 0`。
- 同一个会话、同一个页面上下文里 `fetch('/homepagecontentapi/pod?...')`
  返回 261 KB。
- `leftnavcontentapi/validcompetitions` 返回 `[]`——它本应列出可用联赛。
- 换了 `ctid/cid`（国家、币种）、`pd`（页面描述符）、`tzo` 参数组合
  （共 20+ 组）全部为空。

结论：**服务端按出口 IP 降级**。当前代理出口是荷兰 `185.114.48.105`
（quicksrv.io / ClearStack，机房 IP），bet365 对这类 IP 只放首页，
不给体育内容。需要换成能正常展示赔率的出口（住宅 IP 或 bet365
正常运营区的干净出口）。

## 协议要点

### 不需要 token

`homepagecontentapi/pod` 只要带上网关下发的 cookie 就能调。请求头
`x-net-sync-term` 可以省略。cookie 由访问首页时下发
（`aps03`、`__cf_bm`、`pstk` 等）。

### 请求形状

```
GET https://www.bet365.com/homepagecontentapi/pod
      ?lid=10&zid=0&cid=197&cgid=2&ctid=197
      &pd=%23HO%23P31524%23
```

| 参数 | 含义 |
|---|---|
| `lid=10` | 语言（10 = 简体中文） |
| `cid=197` | 币种 |
| `cgid=2` / `ctid=197` | 国家组 / 国家 |
| `cstid=1&tcstid=1&crid=1` | 只有 `soccertab` / `getsplashpods` 需要 |
| `pd` | 页面描述符，`#` 要编码成 `%23` |

页面描述符：`#HO#P31524#` 首页，`#AS#B1#K^5#` 足球体育页，
`#AC#B1#C1#D1002#E94400598#G40#` 联赛赛程页。

### 接口路由表

`websiteroutingdatacontentapi/routingdata` 返回一张 **136 条**的映射表，
说明哪个页面描述符走哪个接口。这是摸清全部端点的最省事入口：

```bash
# 需要先访问首页拿 cookie
curl -x http://127.0.0.1:7897 -b <cookies> \
  'https://www.bet365.com/websiteroutingdatacontentapi/routingdata?v=1963019705'
```

表里 `t` 是页面类型（`AS` 体育页 / `AC` 联赛比赛页 / `PB` 单场盘口页），
`e` 是接口路径，`m` 是适用范围（运动编号 + `K^` 子页），`p` 是别名。
比如单场全盘口是 `/matchbettingcontentapi/coupon`（`t=AC`）。

更完整的端点清单里有 `splashcontentapi/soccertab`、
`splashcontentapi/soccermarkets`、`matchmarketscontentapi/*`、
`specialeventcontentapi/*` 等 105 个接口。

## 数据格式

响应是 `text/plain`，**不是 JSON**。记录之间 `|` 分隔，字段之间 `;` 分隔：

```
F|CL;IT=#HO#P31524#;PL=brr,cpr,prp,pqp;PV=...;|
EV;NA=欧洲冠军联赛;|
MG;NA=加拉塔萨雷 v 斯图加特;BT=1;SY=pba;CC=UEFA-CL;...;|
MA;NA=加拉塔萨雷;EX=斯图加特;N2=加拉塔萨雷 v 斯图加特;MN=全场赛果;OD=1/1;MA=40;...|
MA;NA=超过;N2=加拉塔萨雷 v 斯图加特;MN=进球总数;HO=2.5;OD=1/3;...|
```

| 类型 | 含义 |
|---|---|
| `CL` | 容器（`IT` 是页面描述符） |
| `EV` | 事件/分组 |
| `MG` | 盘口组；带 `NA` 且含 ` v ` 的就是**一场比赛** |
| `MA` | 盘口选项行 |

`MA` 行里同时有 `N2`（比赛名）、`MN`（盘口名）、`OD`（赔率）才是可用赔率。
其余（球员、串关、广告）一律跳过。

| 字段 | 含义 |
|---|---|
| `N2` | 比赛名 `主队 v 客队` |
| `MN` | 盘口名（`全场赛果` / `进球总数` / `两支球队都得分`…） |
| `NA` | 选项名（队名 / `超过` / `是`…） |
| `EX` | 对手名（1X2 行里用它判断主客） |
| `HO` | 盘线（大小球是 `2.5`） |
| `OD` / `OX` | 赔率，**英式分数**，`OX` 是可选的反向赔率 |
| `CC` / `L3` | 赛事代码（`UEFA-CL`） |

**赔率是英式分数，转欧赔要 +1**：`6/5` → `2.2`，`1/1` → `2.0`。
`parse.fractional_to_decimal()` 处理这个，测试覆盖了 5 种真实格式。

## 代码结构

```
collect/bet365/
    parse.py     记录流解析 + 分数赔率换算（纯函数，无网络）
    http.py      会话管理、接口调用、探活
    adapter.py   接入 Adapter 抽象
tools/bet365_probe.py   可用性自检 + 样本打印
test/test_bet365_parse.py   21 项回归测试，fixture 是真实快照
```

`parse.py` 是**与出口无关**的部分：换成合格出口后，只要把
`list_matches` / `fetch_odds` 换成对应接口，解析层不用改——pod 格式全站一致。

## 换到合格出口后要做什么

1. 把代理换成能正常展示体育内容的出口。
2. 跑 `py tools/bet365_probe.py`，确认 `soccer_tab` 和 `soccer_pods` 字节数 > 0。
3. 用 routingdata 里的 `t=AC` 端点接 `fetch_odds`：
   单场全盘口走 `/matchbettingcontentapi/coupon`，页面描述符从赛程页拿。
4. `list_matches` 接 `/splashcontentapi/getsplashpods` 或
   `/matchmarketscontentapi/soccerupcomingmatches`。

## 与 KessBet 的差异

| 项 | KessBet | bet365 |
|---|---|---|
| 协议 | POST + AES-192 加密请求体 | GET + 明文查询串 |
| 响应 | JSON | 竖线分隔的纯文本 |
| 赔率 | 小数 | **英式分数** |
| 认证 | 硬编码 key，无凭据 | 网关 cookie，无 token |
| 实时推送 | WebSocket（`socketio.kessbet.com`） | WebSocket（`premws-pt*.365lpodds.com`） |
| 反爬 | 出口 IP 黑名单（Cloudflare 403） | 出口 IP 降级（200 + 空体） |
| 单场全盘口 | 一个接口拿全 | 分页 + `changemarket` 逐组拉 |

## 合规

抓的是公开赔率，仅用于个人数据分析。bet365 的服务条款禁止自动化抓取，
且它对无牌照地区做地域封锁——换出口并不能改变这一点。自行评估风险。
